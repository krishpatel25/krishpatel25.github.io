QUESTION ONE

What is a computer actually doing when it runs your program?

Underneath everything you write, something has to hand out memory, notice that you pressed a key, and choose which program gets the processor next. You can use a computer your whole life without ever seeing that layer. I wanted to see it, so I wrote it.

QUESTION TWO · THE ONE I KEEP COMING BACK TO

How does a machine decide what to do next?

A processor is handed a list of instructions and has to get through it as fast as physically possible. The obvious approach — do them one at a time, in order — is also the slowest, because the machine spends most of its life waiting. Every interesting idea in computer architecture is a different answer to "what could we be doing instead of waiting?"

THE MAIN THING I BUILT

A processor that runs ahead of itself

ECE 411 · SYSTEMVERILOG

When an instruction stalls, this one scans further down the list, finds work that is ready, and does that instead — then quietly puts every result back in the correct order before anything downstream can tell. It also guesses which way each branch will go, and when it guesses wrong it unwinds the mistake early rather than paying full price for it.

I measured it on CoreMark and a test suite I wrote by hand. The hard part was never making it fast. The hard part was proving it was still correct while doing all of that out of order.

QUESTION THREE

Could this design survive contact with the physical world?

A design that only runs in simulation is an argument, not a machine. At some point it has to become an arrangement of physical cells on a piece of silicon, with wires whose length costs you time you can never get back — and that is where you find out what your clever idea actually costs.

QUESTION FOUR

And what should we be building all of it for?

A faster machine is only worth having if something worthwhile runs on it. Increasingly that something is machine learning — which is unusually sensitive to the hardware underneath it, and therefore the most interesting thing to design against.

ANSWERED BY

Teaching a compiler to search smarter

IBM-ILLINOIS DISCOVERY ACCELERATOR · 2024–2025

A machine-learning compiler has to decide how to map a calculation onto real hardware, and there are astronomically many ways to do it. I used language-model techniques to throw out the bad options early, then rebuilt the aging pipeline on a modern framework and proved the new one agreed with the old to within two percent.
